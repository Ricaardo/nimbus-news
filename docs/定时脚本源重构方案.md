## 一、现状诊断

### 1.0 两个已确认的排程 Bug

| 源 | 代码注释描述 | 实际 config | 后果 |
|---|---|---|---|
| intraday-breakout | 盘中 10:30 / 14:00 | `["10:30"]` | 午盘异动扫描完全缺失 |
| limit-up-ladder | 盘中 11:00 / 13:30 | `["13:30"]` | 早盘涨停梯队完全缺失 |

这两个不是"优化"问题——`limit_up_ladder.go:16` 和 `intraday_breakout.go:17` 的注释都表明要跑两轮,但 config 只配了一轮,**实际就是少了一半数据**。先修再谈其他。

a-closing-scan 14:45 还有个时间窗口问题:A 股 15:00 收盘,14:45 距收盘还有 15 分钟,涨停池封单/炸板在最后时刻会剧烈变化,14:45 的数据不是收盘状态。加上 closing-scan-backfill 在 16:00 才写入当天数据到 DB,**14:45 做 KNN 预测用的 db 缺失当日样本**,预测质量打折扣。这个延后到 16:10 修复(见步骤 B)。

### 1.1 问题清单

1. **有排程 bug**:intraday-breakout 缺 14:00,limit-up-ladder 缺 11:00(共缺 2 档数据)
2. **有重复**:overseas-trigger 与 morning-scan 的板块映射逻辑重复(sectorToUS vs us2cnSector 两套不同步)
3. **有时间错配**:closing-scan 14:45 跑太早,收盘数据 + backfill db 都还没就位
4. **有缺口**:港股零覆盖、北向资金禁用(--no-northbound)、原油/BTC/汇率无独立源
5. **有浪费**:global-macro 每日跑但月产出(29/30 空转)、weekly-calendar 每日跑但周日输出(6/7 空转)、13 个 Python 脚本写过未接入
6. **有代码血债**:6 个死 Go 源类型(注册未启用)、13 个孤儿 Python 脚本(写过未接入)、sectorToUS/us2cnSector 双映射 drift

## 三、执行步骤

### Step 0 — 即刻修复（2 行 config,5 分钟）

### Step A — 清理（30 分钟,纯删+归档）

| 改动 | 内容 | 注意事项 |

| A3 | a-closing-followup config name → a-morning-followup | 改 config + discord/formatter 的 emoji 映射 |

| A7 | 同步 sectorToUS + us2cnSector | 以 morning_scan.go 为主,将 overseas_trigger.go 的 LCID/IBB/BABA/MSFT/GOOGL 合并进去 |

### Step B — 修复 closing-scan 时间错配（改 Go 代码,半天）

| 改动 | 内容 |
|---|---|
| B1 | a-closing-scan schedule 从 14:45 → 16:10 |
| B2 | 确认 closing-scan-backfill(16:00) 写入的当日数据在 16:10 可读,供 KNN 预测使用 |
