## 二、Futu 数据链路（最高优先级，但当前受限）

### 实际路由

news 平台中调用行情的方式:

```
Go 源 (market_briefing.go / summary.go / morning_scan.go / ...)
  → market.Service.GetMarketQuote(canonical)
    → SymbolResolver.Resolve → native ticker
      → AdapterRegistry (market-data-svc Priority 1)
        → 驻留 Futu worker (:8810 HTTP)
```

### Futu-eligible 条件（`hub.isFutuEligible`）

只有当 symbol 以 `MARKET:` 前缀传入时才会走 Futu worker:

| 前缀 | 例子 | Futu? | 备注 |
|---|---|---|---|
| `US:SPY` | → `AAPL` | ✅ 是 | 通过 normalizeExchangePrefix 或 resolver |
| `HK:0700` | → `0700.HK` | ✅ 是 | 零补齐到 4 位 |
| `SPY` | bare native | ❌ 否 | 没有 `:` 前缀 → adapter chain |
| `000001.SS` | A股 | ❌ 否 | akshare adapter |
| `^VIX` | 指数 | ❌ 否 | Yahoo |
| `CL=F` | 期货 | ❌ 否 | Yahoo |

### 当前真正走 Futu 的路径

**仅有 `datagw /quote` 入口的 Hub 层**会判断 `isFutuEligible`。news 内的 Go 源调的是 `market.Service.GetMarketQuote`,它走的 adapter chain——**不走 Hub 层,所以不走 Futu worker**。

结论: **news 平台目前根本没有走 Futu 数据**。所有 US/HK 行情走的是 adapter chain → market-data-svc(:8810) → HTTP 询价——如果 8810 不可用或拒绝,就一路 fallback 到 Yahoo。

### 正确走 Futu 需要做的

1. news 的 Go 源需要用 `US:` / `HK:` 前缀传 symbol(而非 bare SPY/0700.HK)
2. 经过 `market/hub` 的 `HandleQuote`(当前只有 datagw facade 走这条路由),或者直接 call Futu worker HTTP

**建议方向**:news 的 `market.Service` 调用改为先经过 hub 层,让 Futu-eligible sym 走 :8810 worker。这只需要加一行配置或改 `GetMarketQuote` 内部 dispatch。

## 四、各品类实际数据链路明细

### A 股 (600519 / 000001.SS)

```
news Go 源: morning-scan / closing-scan / evening-report / closing-briefing / ...
  → market.Service.GetMarketQuote(SH.000001)
    → SymbolResolver: SH.000001 → 000001.SS (exchange-prefix normalize)
      → AkshareAdapter(5): CanHandle(.SS)→true
        → py-worker(:8824)/akshare/quote?symbol=000001
          → Sina Finance 实时API
      → YahooAdapter(10): fallback
```

**实际数据**: Sina Finance 实时 API(非 Futu)
**延迟**: ~100ms
**可靠性**: ⭐⭐⭐⭐ Sina 免费稳定,但 py-worker 有单点

### 港股 (0700.HK / 2800.HK)

```
news Go 源: market_briefing / summary
  → market.Service.GetMarketQuote(0700.HK)
    → SymbolResolver: 0700.HK → 0700.HK (pass-through)
      → MarketDataAdapter(1): CanHandle(.HK)→true, CanHandle bare?→false
        → isMarketDataBareTicker: "0700.HK" 有. → false
        → 所以 MarketDataAdapter 不会处理 bare ticker
      → AkshareAdapter(5): CanHandle(.HK)→false
      → YahooAdapter(10): CanHandle→true
          → query1.finance.yahoo.com/chart/0700.HK
```

**实际数据**: **Yahoo Finance**(fallback!)——不走 Futu worker
**延迟**: ~500ms + 有限流风险
**可靠性**: ⭐⭐ Yahoo 429 频繁(今日 36 次 failed to get quote)

### 美股 (SPY / AAPL)

```
news Go 源: market_briefing / summary
  → market.Service.GetMarketQuote(SPY)
    → SymbolResolver: SPY → SPY
      → MarketDataAdapter(1): CanHandle("SPY") → true
        → isMarketDataBareTicker: 3字母全大写 → true
          → :8810/quote?symbol=US:SPY
```

**实际数据**: **market-data-svc(:8810)** → Futu worker
**延迟**: ~50ms
**可靠性**: ⭐⭐⭐⭐⭐(本地服务)

### 黄金 (GLD / GC=F)

```
news Go 源: market_briefing / summary
  → market.Service.GetMarketQuote(GLD)
    → market-data-svc(1): CanHandle("GLD") → true → 8810
    → fallback: Yahoo(10)
```

**实际数据**: 优先 Futu worker(:8810), fallback Yahoo
**延迟**: ~50ms(Futu) / ~500ms(Yahoo)
**可靠性**: ⭐⭐⭐⭐

### 原油 (CL=F)

```
news Go 源: market_briefing / summary
  → market.Service.GetMarketQuote(CL=F)
    → market-data-svc(1): CanHandle("CL=F") → false(有 = 符号)
    → akshare(5): .SS/.SZ? → false
    → Yahoo(10): CanHandle → true
```

**实际数据**: **纯 Yahoo**(所有前面的适配器都不能处理 `=F` 后缀)
**延迟**: ~500ms
**可靠性**: ⭐⭐ Yahoo 429

### BTC (BTC-USD / BTC-USDT)

```
news Go 源: market_briefing / summary
  → market.Service.GetMarketQuote(BTC-USD)
    → Binance(5): CanHandle→true(USDT后缀不匹配,但...)
```

**实际数据**: Binance/OKX/CryptoAlt 轮询
**延迟**: ~200ms
**可靠性**: ⭐⭐⭐⭐⭐

### VIX (^VIX)

```
news Go 源: vix_term script → data_access facade → datagw /quote
  → data_access 内部调用: IDX:VIX
    → ToHubSymbol: → ^VIX

```

**实际数据**: **纯 Yahoo**
**可靠性**: ⭐⭐

## 五、问题诊断

### 5.1 港股走 Yahoo 是当前最大性能问题

`0700.HK` 不符 `isMarketDataBareTicker`(包含 `.`),所以 market-data-svc(priority 1)跳过了它。Yahoo(priority 10)接了但限流频繁(今天 36 次 error)。

**根因**:港股有 `.HK` 后缀但 market-data-svc adapter 只接受 `*:HK` 格式的 bare ticker:
- `CanHandle("0700.HK")` = 有 `.` → false ← 就是这个条件导致港股永远跳过了 8810

**修复**:修改 `marketdata.go:CanHandle` 中对 `.HK` 的处理——识别 `.HK` 后缀并路由到 8810。

### 5.2 News 平台不从 Futu worker 读数

`market/hub/hub.go` 的 `isFutuEligible` 只在 Hub 层工作。news 直接调 `market.Service.GetMarketQuote` → adapter chain,不走 Hub。所以 Futu worker 实际只服务 datagw facade 的 `/quote` 入口。

**根因**:`market.Service` 内没有 Futu 优先 dispatch。Futu 路由是 Hub 层逻辑,不在 Service 层。

### 5.3 原油走纯 Yahoo

`CL=F` 有 `=` 符号,所有适配器的 `CanHandle` 都返回 false,只有 Yahoo 接了。对于交易标的来说,Yahoo 的限流(429)是单点脆弱。

### 5.4 VIX 走纯 Yahoo

`^VIX` 有 `^` 前缀,同上有适配器盲区。这就是为什么 vix_term 脚本经常返回空——Yahoo 限流了就什么都没了。

## 六、优化建议（按优先级）

### P0: 修港股不走 Futu worker

**改动**:`datasources/market/adapters/marketdata.go`
```go
func (a *MarketDataAdapter) CanHandle(symbol string) bool {
    upper := strings.ToUpper(symbol)
    if strings.HasSuffix(upper, ".HK") {
        return true  // <-- 加这行,让港股也走 :8810
    }
    // ...
}
```

**效果**:港股行情从 Yahoo(500ms) 切换到 Futu worker(50ms),消除 Yahoo 限流影响。

### P1: News 的 market.Service 加 Futu 优先路由

**改动**:`datasources/market/adapter.go` 或 `hub.go` 中,在 adapter chain 启动前,先检查 Futu-eligible 并尝试 worker。

简单方案:让 `MarketService.GetMarketQuote` 也检查 Futu-eligible,如果符合且 worker 可用则先走:

```go
// 在 market.Service 中加
func (s *MarketService) attemptFutuWorker(canonical string) (*types.MarketQuote, error) {
    if isFutuEligible(canonical) { // 复用 hub 的判断
        // call :8810/quote?symbols=xxx
    }
    return nil, nil
}
```

### P2: 修复原油走势

**方案 A**:`marketdata.go` 的 `CanHandle` 中把 `CL=F` / `GC=F` 这类期货 symbol 也接受为 `isMarketDataFutures`。

**方案 B**:新 adapter `FuturesAdapter`, priority 3,处理 `=F` 后缀合约。

### P3: VIX 指数路由

`^VIX` 类指数合约建议在 `marketdata.go` 中加 `^` 前缀支持,让 8810 尝试处理。
